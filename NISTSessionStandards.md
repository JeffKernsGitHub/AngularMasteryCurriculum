The common NIST rules for **session management** are primarily found in **NIST Special Publication (SP) 800-63 (Digital Identity Guidelines)** and **NIST SP 800-53 (Security and Privacy Controls for Federal Information Systems and Organizations)**, particularly control **AC-12 (Session Termination)**.

These guidelines focus on secure session creation, protection, and most notably, termination.

---

## 🔒 Key Session Management Rules (NIST SP 800-63B)

NIST SP 800-63B, *Authentication and Lifecycle Management*, defines the requirements for session lifetimes and termination, which are determined by the **Authentication Assurance Level (AAL)** associated with the session.

| Requirement | Description | Example Guidance for AAL2 / AAL3 |
| :--- | :--- | :--- |
| **Inactivity Timeout** | Automatically terminates a session after a period of user **inactivity**. This prevents session hijacking if a user walks away from a device. | **AAL2:** Recommended 1-hour inactivity timeout. **AAL3:** Recommended 15-minute inactivity timeout. |
| **Overall Timeout** | Limits the total duration of an authenticated session, regardless of user activity. This forces periodic **re-authentication** to mitigate risk from long-term compromised session tokens. | **AAL2:** Recommended 24-hour overall timeout. **AAL3:** Recommended 12-hour overall timeout. |
| **Session Termination** | Sessions **SHALL** be terminated when either the inactivity or overall timeout expires. Successful re-authentication **SHALL** reset both timeouts. | Users should be required to re-authenticate completely after a timeout. |
| **User-Initiated Termination** | Sessions **SHOULD** provide a readily accessible mechanism (e.g., a **Logout** button) for subscribers to terminate their session when finished. | Provide a clear, visible "Log Off" capability. |
| **Warning Mechanisms** | The service **MAY** alert the user that the session is about to be terminated due to an approaching timeout, allowing them to extend the session (e.g., by re-authenticating or generating activity). | Display a warning message, e.g., "Your session will expire in 5 minutes." |

> **Note:** NIST provides **recommended** values for AALs, but ultimately, organizations must set timeout periods based on the **sensitivity of the information** being accessed and the system's overall **risk profile** (a **risk-based approach**).

## 🛡️ General Session Security & Control (NIST SP 800-53)

NIST SP 800-53, specifically control family **AC (Access Control)**, reinforces these practices with system-level controls:

* **AC-12: Session Termination**
    * Requires the system to automatically terminate a user's **logical session** after an **organization-defined** period of inactivity or upon other defined trigger events (e.g., time-of-day restrictions).
    * **AC-12(1) User-initiated Logouts:** Requires providing a logout capability for user-initiated communications sessions.
    * **AC-12(2) Termination Message:** Requires displaying an explicit logout message upon session termination.
    * **AC-12(3) Timeout Warning Message:** Requires displaying an explicit warning message before a session ends.
* **AC-10: Concurrent Session Control**
    * Limits the number of concurrent sessions for a specific account or account type to an **organization-defined** number. This mitigates unauthorized use and resource exhaustion.

## 🔑 Session Binding and Secrets

The guidelines also include requirements for the session token itself, often referred to as the **session secret**:

* **Secure Transport:** Session secrets (like cookies or bearer tokens) **SHALL** be accessible only on **secure (HTTPS)** sessions.
* **HTTP-Only & Scoping:** Session secrets **SHOULD** be tagged as **inaccessible via JavaScript** (HttpOnly) and scoped to the minimum practical hostnames and paths.
* **Entropy:** The session secret **SHALL NOT** be guessable and needs to have sufficient **entropy** to resist guessing attacks, generated by an approved random bit generator.
* **Non-Persistent Secrets:** Session secrets used as bearer tokens **SHOULD NOT** be persistent (i.e., retained across application or device restarts).
