Angular Forms Explanation

Reactive Forms (Recommended First)

Reactive forms provide a model-driven approach to handling form inputs whose values change over time. They are built around observable streams, making them more robust, scalable, and testable. This approach is generally recommended for complex forms or when you need more control over the form's data flow.

Setup:

  • In your component, create a FormGroup to represent the form, and FormControl instances for each input field.
  • Bind the FormGroup to the form using [formGroup]="yourFormGroup" and FormControls to inputs using formControlName="fieldName".
  • Ensure ReactiveFormsModule is imported into the component's imports array.

Form Controls & Validation:

Each input field is explicitly defined as a FormControl in your component's TypeScript. Validation rules are also defined programmatically within the FormControl definition using Validators.

@if (reactiveForm.get('username')?.invalid && reactiveForm.get('username')?.touched) {
@if (reactiveForm.get('username')?.errors?.['required']) { Username is required. } @if (reactiveForm.get('username')?.errors?.['minlength']) { Username must be at least 3 characters. }
}
@if (reactiveForm.get('email')?.invalid && reactiveForm.get('email')?.touched) {
@if (reactiveForm.get('email')?.errors?.['required']) { Email is required. } @if (reactiveForm.get('email')?.errors?.['email']) { Please enter a valid email. }
}
@if (reactiveForm.get('password')?.invalid && reactiveForm.get('password')?.touched) {
@if (reactiveForm.get('password')?.errors?.['required']) { Password is required. } @if (reactiveForm.get('password')?.errors?.['minlength']) { Password must be at least 6 characters. }
}

Template-Driven Forms (Comparison and Use Cases)

Template-driven forms are easier to set up for simple forms. They rely heavily on directives in the template to create and manage the form model implicitly. While quicker for basic scenarios, they offer less control and can become harder to manage for complex validation or dynamic form structures.

Setup:

  • Use ngModel directive on input elements to bind them to properties in your component.
  • Add #myForm="ngForm" to your <form> tag to get a reference to the NgForm directive.
  • Ensure FormsModule is imported into the component's imports array.

Comparison & Use Cases:

  • Reactive Forms: Best for complex forms, dynamic forms, custom validation, and when you need to unit test form logic easily. The form model is defined explicitly in the component.
  • Template-Driven Forms: Suitable for simple forms, quick prototypes, or when you prefer to define most of your form logic directly in the template. The form model is inferred from the template.
@if (nameField.invalid && nameField.touched) {
@if (nameField.errors?.['required']) { Name is required. }
}
@if (emailField.invalid && emailField.touched) {
@if (emailField.errors?.['required']) { Email is required. } @if (emailField.errors?.['email']) { Please enter a valid email. }
}

Signal-Based Forms (Modern Approach)

Signal-based forms leverage Angular's new signal primitive to manage form state and validation. While there isn't a dedicated "SignalFormGroup" yet, you can build reactive forms using individual signals for each input and computed signals for derived state like validity. This approach offers fine-grained control, explicit change detection, and can lead to more performant applications.

Setup & Validation:

  • Define individual signal() for each form input in your component.
  • Use computed() signals to derive validation status based on input signals.
  • Bind input values using [value] and update signals on (input) events.
  • Manage "touched" state with separate signals to control when validation messages are shown.
@if (signalNameTouched() && !isSignalNameValid()) {
Name must be at least 3 characters.
}
@if (signalEmailTouched() && !isSignalEmailValid()) {
Please enter a valid email.
}
@if (signalMessageTouched() && !isSignalMessageValid()) {
Message cannot be empty.
}
